# Nightgauge Homebrew Tap

Homebrew cask for the [Nightgauge](https://github.com/nightgauge/nightgauge) CLI —
an AI-powered Issue-to-PR pipeline.

```bash
brew install nightgauge/tap/nightgauge
```

The tap is reserved for Nightgauge's first public release. There is no published
cask yet; the command above will work once the release is available.

## What this repository distributes

Only the cask definition — a pointer to release artifacts built and published in
the [core repository](https://github.com/nightgauge/nightgauge). No binaries are
stored here. `brew install` downloads the archive from that repository's GitHub
Release and verifies it against the SHA-256 recorded in the cask.

Cask files are generated by GoReleaser on each release. **Do not edit them by
hand** — the next release overwrites them.

## Verifying what you installed

A tap is a distribution channel: whatever is on its default branch is what
`brew install` fetches. You should be able to check what you are running rather
than trust that sentence.

Every release publishes three things you can verify independently.

**1. Checksums.** Each release includes `checksums.txt` (SHA-256) covering every
archive:

```bash
gh release download vX.Y.Z --repo nightgauge/nightgauge --pattern 'checksums.txt' --pattern '*.tar.gz'
shasum -a 256 -c checksums.txt --ignore-missing
```

**2. Build provenance.** Releases carry a GitHub build attestation, so you can
confirm an archive was produced by this project's release workflow rather than
uploaded by hand:

```bash
gh attestation verify <archive>.tar.gz --repo nightgauge/nightgauge
```

This is the check that matters most. A checksum only proves the file matches
what the release says; the attestation proves _which workflow, in which
repository, at which commit_ produced it.

**3. An SBOM.** Each archive ships an SPDX-JSON software bill of materials
(`*.spdx.sbom.json`) listing its dependencies, covered by the same attestation.

## How a release reaches this tap

GoReleaser opens a **pull request** against this repository rather than pushing
to `main`, and a branch ruleset requires it. A compromised release token can
therefore only _propose_ a cask, never publish one.

One consequence worth knowing: a release is not fully published until that pull
request is merged. In between, the GitHub Release carries the new version while
`brew install` still serves the previous one.

## Reporting a problem

Vulnerabilities: follow the disclosure path in the
[organization security policy](https://github.com/nightgauge/.github/blob/main/SECURITY.md).
Do not open a public issue for a security report.

Anything else: [open an issue](https://github.com/nightgauge/nightgauge/issues)
in the core repository.
